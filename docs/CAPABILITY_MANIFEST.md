# Godot Game Test Lab capability manifest

`evavo.capabilities.json` is the machine-readable declaration of the specialist work this repository can perform. It is advisory discovery evidence for Development Studio, Local Compute, Automated Testing, MCP routers and other EVAVO control planes. It is not a blanket execution grant.

## Authority

Godot Game Test Lab independently validates and admits evidence from external Godot projects. It may inspect source, provision verified managed editors, execute bounded validation, retain evidence outside target source authority and write create-only admission reports where a named contract permits that effect.

It does not repair a target repository, mutate product truth, manufacture human decisions, approve language, publish a build, deploy a store release, change credentials or create financial commitments.

## Live capability surface

The manifest declares fourteen capabilities:

1. privacy-safe Automated Testing readiness;
2. checksum-verified managed Godot provisioning;
3. read-only project inspection and integrity audit;
4. authoritative Godot import, boot, record and export evidence;
5. exact-head guarded plural-localization runtime validation;
6. exact-head read-only stable-ID application-bundle admission;
7. exact-SHA native authored QA;
8. exact-SHA concurrent multiplayer role QA;
9. deterministic fresh-process bot QA;
10. no-network Linux sandbox QA;
11. retained gameplay media and audio analysis;
12. exact installed game-asset delivery admission;
13. Brass visual-animation admission;
14. exact-byte rig-motion acceptance v4.1.

### Guarded plural-localization capability

`testlab.localization.plural-runtime` consumes a fingerprint-valid `localization-godot-plural-testlab-request-v1` produced by Localization Manager. The canonical command is:

```powershell
godot-lab-localization-plural `
  C:\GitRepos\TargetGodotGame `
  --request C:\evidence\plural-request.json `
  --artifacts C:\evidence\plural-validation
```

The guarded route requires an exact clean Git head, verifies installed CSV bytes, runs authoritative Godot import and reviewed plural probes, removes transient probe material, retains external evidence and leaves target mutation, repair, linguistic approval, release and publication authority false.

### Stable-ID application-bundle admission

`testlab.localization.stable-id-bundle-admit` consumes a fingerprint-valid `localization-godot-stable-id-application-bundle-v1` produced by Localization Manager. The canonical command is:

```powershell
godot-lab-localization-stable-id-bundle `
  C:\GitRepos\TargetGodotGame `
  --bundle C:\evidence\stable-id-application-bundle.json `
  --pretty
```

This route is read-only. It:

- requires an exact clean target Git head and matching GitHub origin;
- verifies current tracked source bytes against the exact head;
- verifies proposed scene bytes without writing them;
- verifies source-locale CSV bytes without creating the file;
- proves stable-ID coverage and source-message provenance are exact;
- rechecks target head, status and source bytes after admission;
- grants no apply, runtime-registration, commit, push, release or publication authority.

A passed bundle admission is byte-integrity evidence only. It is not Godot import or runtime proof and cannot turn a pending product review into an approved decision.

## Validation

The dependency-free checker is:

```powershell
python scripts/check_evavo_capability_manifest.py
```

It runs the retained broad Test Lab source checker and then validates both localization specializations. It verifies:

- the exact fourteen capability IDs and effect sets;
- the shared capability schema and repository identity;
- exact package console bindings;
- real repository paths for declared source entrypoints;
- live source markers for managed engines, MCP, native, multiplayer, bot, sandbox, media and admission paths;
- plural request/report schema authority boundaries;
- stable-ID bundle/report schema authority boundaries;
- guarded source, CLI and documentation markers;
- absence of target publication and financial authority.

`check_evavo_capability_manifest_legacy.py` is retained as a historical broad-source checker and imported by the current wrapper. It is not a second public command.

The focused GitHub Actions workflow compiles capability-bound sources and runs capability, plural-localization and stable-ID bundle regression tests. General CI still owns the complete repository test, Ruff, wheel and clean-tree gates.

## Discovery rule

A router may use this manifest to select a specialist, but actual execution must still satisfy the selected entrypoint's path, exact-SHA, evidence-root, engine, network, review and effect policy. Declaring a capability never upgrades a caller's authority.
