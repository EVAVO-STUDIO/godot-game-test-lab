# Godot Game Test Lab capability manifest

`evavo.capabilities.json` is the machine-readable declaration of the specialist work this repository can perform. It is advisory discovery evidence for Development Studio, Local Compute, Automated Testing, MCP routers and other EVAVO control planes. It is not a blanket execution grant.

## Authority

Godot Game Test Lab independently validates and admits evidence from external Godot projects. It may inspect source, provision verified managed editors, execute bounded validation, retain evidence outside target source authority and write create-only admission reports where a named contract permits that effect.

It does not repair a target repository, mutate product truth, approve language, publish a build, deploy a store release, change credentials or create financial commitments.

## Live capability surface

The manifest declares thirteen capabilities:

1. privacy-safe Automated Testing readiness;
2. checksum-verified managed Godot provisioning;
3. read-only project inspection and integrity audit;
4. authoritative Godot import, boot, record and export evidence;
5. exact-head guarded plural-localization runtime validation;
6. exact-SHA native authored QA;
7. exact-SHA concurrent multiplayer role QA;
8. deterministic fresh-process bot QA;
9. no-network Linux sandbox QA;
10. retained gameplay media and audio analysis;
11. exact installed game-asset delivery admission;
12. Brass visual-animation admission;
13. exact-byte rig-motion acceptance v4.1.

### Guarded plural-localization capability

`testlab.localization.plural-runtime` consumes a fingerprint-valid `localization-godot-plural-testlab-request-v1` produced by Localization Manager. The canonical command is:

```powershell
godot-lab-localization-plural `
  C:\GitRepos\TargetGodotGame `
  --request C:\evidence\plural-request.json `
  --artifacts C:\evidence\plural-validation
```

The console alias resolves to `godot_game_test_lab.localization_plural_runtime_cli:main`. The guarded route:

- requires an exact clean Git head and supported GitHub origin;
- verifies the exact project-relative CSV SHA-256 and byte count;
- runs normal Test Lab integrity, import and bounded boot validation;
- runs reviewed integer plural lookup probes through Godot;
- removes transient ignored probe material;
- rechecks Git head, status and CSV identity after execution;
- retains evidence outside the Lab and target repositories;
- leaves target mutation, repair, linguistic approval, release and publication authority false.

The lower-level compatibility modules remain implementation surfaces. They are not the public authority route.

## Validation

The dependency-free checker is:

```powershell
python scripts/check_evavo_capability_manifest.py
```

It runs the retained broad Test Lab source checker and then adds the guarded plural-localization contract. It verifies:

- the exact thirteen capability IDs and effect sets;
- the shared capability schema and repository identity;
- exact package console bindings;
- real repository paths for declared source entrypoints;
- live source markers for managed engines, MCP, native, multiplayer, bot, sandbox, media and admission paths;
- plural request/report schema authority boundaries;
- guarded runtime, wrapper and documentation markers;
- absence of publication and financial authority.

`check_evavo_capability_manifest_legacy.py` is retained as a historical broad-source checker and imported by the current wrapper. It is not a second public command.

The focused GitHub Actions workflow compiles the capability-bound sources, parses the Windows wrapper and runs the capability plus all plural-localization regression tests. General CI still owns the complete repository test, Ruff, wheel and clean-tree gates.

## Discovery rule

A router may use this manifest to select a specialist, but actual execution must still satisfy the selected entrypoint's path, exact-SHA, evidence-root, engine, network, review and effect policy. Declaring a capability never upgrades a caller's authority.
